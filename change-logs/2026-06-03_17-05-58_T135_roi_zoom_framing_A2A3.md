# T135:ROI 框选改造(方案 A2+A3)— 两阶段放大 + 裁剪预览确认

## 1. 任务概述

降低小目标(牌角/弃牌区等)框选风险。用户拍板 **A2(两阶段放大)+ A3(裁剪预览确认)**,**砍掉 A1(fromCenter)**——用户:"无法确定我点的中心是否真中心,fromCenter 反而更糟"。设计见 `requirement-discussions/roi-framing-tool-design.md`(方案 A)。
**相邻任务**:`2026-05-25_19-27-00_roi_config_all_seats_batch_mode.md`(place_roi_by_click / --copy-size 点选模式,本次未动)。

## 2. 假设清单

- cv2.selectROI 在【放大后的裁剪图】上调用,返回坐标 = 该图(放大尺度)像素 → 除以 scale + 加裁剪起点 = 原图坐标(`_fit_window` 注释:selectROI 坐标在传入图像空间,与窗口显示缩放无关)。
- 放大裁剪图尺寸小,`_fit_window` 不会再缩小它 → 阶段2 坐标=放大图原尺度。
- 保持 `select_roi(window_name, img) -> (x,y,w,h)|None` 契约不变 → 上游 caller 无需改。

## 3. 文件变更清单

- `tools/roi_geom.py`(**新增,纯函数无 cv2**):`map_zoomed_roi(coarse, fine, scale, pad, img_w, img_h)` 坐标回映 + clamp。隔离"算错就全偏"的核,使其能在无 cv2 的 Linux 单测。
- `tests/test_roi_geom.py`(**新增**):4 例(精确回映 / 左上 clamp / 尺寸 clamp / 精框跳过用粗框)。**Linux 跑通 4/4**。
- `tools/roi_config.py`(改):
  - import `roi_geom.map_zoomed_roi`(try/except 兼容两种调用)+ 常量 `ZOOM_SCALE=8` / `ZOOM_PAD=24`。
  - 新增 `_confirm_crop`(A3:放大显示裁剪块,SPACE 存/R 重/ESC 跳)。
  - 重写 `select_roi`(A2:粗框→裁剪放大→精框→回映→预览确认循环);**保持返回契约不变**。

**可能 failure mode(我未验)**:
1. 放大窗尺寸过大/超屏(`_fit_window` 上限 1280×720,理论会缩;若仍超屏调 ZOOM_SCALE)。
2. 按键码在你 OpenCV 版本不符(SPACE=32 / ESC=27 / R;若无响应报我)。
3. 坐标偏移(理论已单测,但若放大窗被 `_fit_window` 二次缩放导致 selectROI 坐标非放大尺度 → 会偏;**这是我最担心的一条,重点核**)。
4. putText 英文(避开 cv2 不能渲染中文)。
