## 一、纵向承重分层(下层承上层,荷载向下、数据向上)

### L0 地质层 — 采集 (Capture)
- **是什么**:截图帧 + manifest(盲注/ante/帧率)。`record_frames.py`。
- **比喻**:你要打桩进去的**地质**。地质烂(漏帧、动作太快没采样、遮挡)→ 桩再准也白搭。
- **硬约束**:**image-only 红线** = 只准航拍勘察(截图+OCR+图像 hash),禁钻孔取样(DOM/插件/抓包)。
- **可调**:帧率、decimate、窗口/多屏后端(DXcam 负坐标失败 → mss)。

### L1 基础层 — ROI + 信号(基桩)
- **ROI = 桩位**:在每帧哪个矩形里探测。`roi_config.py`(框选工具改造见 [[roi-framing-tool-design]])。
- **基桩(高置信、可承重)**:二值/高对比/**不 OCR** 的信号 ——
  - D 按钮位移(亮度,切手)· 公共牌张数(白占比,分街)· +xx 出现(phash 布尔,结算)· **[规划] 牌角两牌=活跃集**(phash 对参考)。
  - 这类实测 ~99%,是**承重桩**。
- **弱桩(低标号、不可承重)**:OCR 读数字 —— stack 金额 · 下注区 · 底池 · 动作词。70–92%。
- **三档识别器**(constraint-solver §):A 类别 CNN / B 数字弱档 / C ID 缓存。

### L2 圈梁层 — 对账求解 (Reconciliation / Solver) ★当前关键路径
- **是什么**:把孤桩的荷载**主动对账、重新分配**成刚性整体。`pipeline/solver.py`(砖2)。
- **比喻**:真实圈梁坐桩顶、托柱脚,是**承上启下的荷载转换构件**——不是"又一个信号",是**主动推理层**。
- **三件武器**:
  1. **多信号过定交叉**:同一事实多个独立信号互证(牌角∩后续街有动作∩摊牌/+xx∩守恒)。
  2. **守恒/合法性**:底池守恒(~92% 锚)+ 德州下注规则(注级单调、全下终局、不能自加)。
  3. **加法反推**:活跃集 × 注级 → 补"看不见的末位跟注"等隐藏动作(**加法,不是减法**;减法 v1 净亏已废,见 §20)。
- **设计依据**:[[ring-beam-inference-design]](22 维 + 10 联立)。

### L3 框架层 — 牌局重建 (Reconstruction)
- **是什么**:基础+圈梁之上,产出**高质量牌局**:分街 / 切手 / 每座每街动作序列 / 手谱。`pipeline/reconstruct.py` + 分段。
- **现状**:筹码动作 recall 标准桌 98–99%;precision 受弱桩标号掣肘(见正交轴)。

### L4 功能层 — Function
- 用户画像(VPIP/PFR/AF/NIT 假面识别)· 玩家 ID/别名库 · 疑惑牌局复盘 · 保险/边池统计。`dashboard/`。
- **这是项目终极目标**(对手画像);其余层都为它服务。

### L5 界面层 — Interface
- 具体功能交互 UI(dashboard 页面/统计视图)。

### L6 解释层 — LLM(旁挂,受限)
- LLM **仅**做策略建议 / 牌局自然语言解释。
- **红线**([[llm-explanation-layer-only]]):**禁止碰结构构件**(不做运维/数据修复/规则化决策)。= 只许看成品提建议的顾问,不许动承重墙。

## 二、正交轴:材料标号(信号可靠度)
**不是一层,是每根桩的属性。** 决定它能承什么荷载。

| 信号 | 标号 | 能承的荷载 |
|---|---|---|
| D按钮 / 公共牌 / +xx-phash / 牌角 | ~99% 承重 | 切手/分街/活跃集/守恒**锚** |
| 底池 pot | ~92% | 守恒锚(够用) |
| stack **跌幅存在** | recall 98% | 动作**发生**(承重) |
| stack **金额** / 下注区 / 动作词 | 70–90% 弱 | 仅提示/兜底,**不可当守恒锚** |

**铁律:承重荷载只走高标号桩。** stack 金额不可锚、底池才是锚([[constraint-solver-paradigm]]),根因就在此。误把弱桩当承重桩 = 地基沉降。

## 三、横切(规范 / 监理,贯穿所有层)
- **验收规范**:真值 fixture(`truth_*.txt`)+ 离线自测 + recall/precision 度量。"测试通过"= Linux 静态 + Win 实测两段。
- **环境不对称**([[env-tooling-constraints]]):Linux(我可达、算力弱)写码+轻验;Win(我不可达、5070Ti)跑重模型+实测;git push/pull 同步。**改完先 push 再让用户验**。
- **治理**([[governance-protocol-active]]):4-mode + 10 红线 + 每 turn Router 自检。
- **数据驱动**([[feedback-data-driven-mandate]]):每个数字/推断必 ground;1 sample 标"不可外推";凭印象立即 push back。

## 四、荷载流向 + 误差传播(关键认知)
- **数据向上流**(信号→重建→画像→UI);**误差也向上流**。
- **下层裂缝,上层补不平**:precision 里"OCR 读偏"那部分,画像层/求解器永远修不好——**根在材料标号(弱桩),只能换桩(OCR 升级 T133)**,不能靠楼上装修找平。
- **推论:在正确的层修问题。** recall(捕获)是不可逆的——漏在 L0/L1 没采到,上面无中生有不了;所以"捕获 95%"是 L0/L1 的硬指标,而 precision 噪声交给 L2 圈梁过滤。

| **L2 圈梁** | 🚧 **正在浇——关键路径**。求解器减法 v1 净亏已废,改**加法反推**;活跃集基桩待建 |

## 六、设计公理(选材/施工的第一性原则)
1. **抓持久态,不抓瞬态**(动作字幕/牌角标记是状态;弃牌动画是事件)。
2. **多信号过定,不信任单点**(圈梁拉孤桩成筏板)。
3. **基桩选材:二值高对比 > OCR**(按钮 99% vs 读数 70-90%)。
4. **荷载路径走高标号桩**(守恒锚用 pot 不用 stack 金额)。
5. **95% 是 recall(捕获)目标**;precision 交圈梁过滤。
6. **image-only**;**LLM 仅解释、禁碰结构**。
7. **离线 replay 先扎实,live(边打边算)是未来轴**,架构留缝不提前盖。
