## §1 问题:一个 1–2px 的漂移,让 hero(s0)整场动作全丢

### 现象(实测,2026-06-20)
- s0(=hero)某场 **251 手、真实动作 = 0**,其它 7 座正常(219–402)。s0 唯一漏出的是 all_in。`(实测 DB §8.2/8.3)`
- 赢家铁证:有一手 `winners_endpoint:[0]`(两路赢家来源一致认 s0 赢),s0 真实动作却 = 0。**赢家不可能弃 → 动作确系丢失,非真弃。** `(实测 DB)`
- 静默级联:零报错,occupancy/盲注注入照常,只有动作悄悄全丢。`(实测)`

### 根因链(代码 + 实测交叉确认)
1. **UI 微调** → s0 整座 ROI **刚性平移 1–2px**(分辨率仍 1454×1287 未变;只 s0 漂、别座没动 → 偏 hero 面板一次性改版,非全局缩放)。`(实测:新旧帧 draw_roi 叠帧对比)`
2. **容差差异致选择性崩**:`card_marker`(7×7 块 phash,hamming≤8 容差)**吃掉了同样的 1–2px 漂移**(ham 仍≈0,误导成"它没漂");`action`("首字"razor 框,零容差)**同样漂移即移出笔画 → phash 匹配归零**。`(实测 + 代码)`
3. **action phash 是动作发射的闸**:`orchestrator.py:2663` `if not action_text: continue` —— 真实动作(call/check/raise/bet)发射**被 action 框 phash 匹配门控**,不是纯 stack 驱动。phash 落空 → 该座该帧整个跳过 → 动作不入库。all_in 例外(走 stack→0 独立触发,绕过闸,故唯一能漏出)。`(代码)`
4. **重框 action 但锚没动 → 仍失败**:action_refs 按词存(过牌/跟注/下注/加注,8座×4词=32锚),s0 的锚采于**旧框位置**;只挪框不重采锚 = 旧锚作废,必然不匹配。`(实测 + 代码)`

> 详见排障全链与命令:`docs/ops-cheatsheet.md` §10 Worked example。

## §2 战略判断:这是"一次性改版"还是"对抗性随机抖动"?

**数据诚实**:两者后果天差地别,现有证据更偏"一次性改版":
| 证据 | 指向 |
|:---|:---|
| 只 s0 漂、别座没动 | 随机反抖会全座一起抖 → 更像**一次性改 hero 面板** |
| 06-15 s0 还正常、06-19 才崩 | 像版本变更时点,不像每局随机 |
| 分辨率没变、偏移小且稳定 | 像固定新布局,不像每次不同 jitter |

**但担忧依然成立**:WePoker 曾因"外挂"封号([[wepoker-tos-ban-risk]]),是**对抗性平台**,故意抖 UI 当反自动化手段在其动机/能力内。**recurrence 高度可能**(未来更新,甚至升级成故意/随机/变幅)。
→ **结论**:不论这次是哪种,**像素级硬框这套地基本身太脆**,是真问题。抗漂值得立项。

## §3 设计:per-seat 锚 + 相对 ROI + 自动配准(用户主张 + 工程加固)

### 核心洞察(用户,实测支撑)
**座内 ROI 相对位置不变**——s0 每个 ROI 偏移量相同(整座刚性平移)。`(实测)`
→ 只需为每座定一个**锚**,把该座所有 ROI 表示为"锚 + 相对偏移";漂移时只需重新定位锚,其余 ROI 跟着平移。

### 复用既有(非从零)
- `tools/roi_derive.py` 已实现"**card_marker 锚 + 相对模板 + 镜像**派生全座 ROI" —— 正是"锚+相对"模型。`(代码)`
- `card_marker` 本身就是 per-seat 锚(牌背角 phash)。
→ 本方案 = 把 roi_derive 的"锚+相对"从**离线工具**升级为**运行时自动配准**。

### 三个工程点(必须拍死,否则方案漏)
1. **锚分两角色,别混用**:
   - **canary 锚**(报警)= card_marker:容差大,适合"还对齐吗",**但正因容差大当不了尺子**(漂 1–2px ham 仍 0,测不出偏移量)。
   - **配准锚**(测量)= 锐角特征(用户提议:牌背角"白 3/4 红 1/4"):用模板匹配/互相关找峰值,**算出精确 (dx,dy)**。
2. **"重选锚"必须【自动】**:漂了若还手动重框,"频率不可控"会拖死。正解 = **邻域搜索自动配准**:锚期望位对不上 → ±K px 窗口模板匹配找真实位 → 自动算偏移 → 全座 ROI 平移。零人工。能扛多大漂 = 窗 K(大窗更慢 + 防附近假匹配,必要时由粗到细两级)。
3. **校验时机:不止开录一次**:版本更新开录校一次够;但中途/每局抖则漏。**card_marker 本就每 tick 在比 → 做成持续监控,检出座位级漂移即自动触发该座重配准**。这才治"频率不可控"。

### 合规框架(识别层冻结 R-5)
**把自动配准做成冻结检测器的【上层】,不改检测器本身。**
- 配准只干一件:检测器跑之前把 ROI 坐标修正好。card_marker/action phash/数字 OCR **一行不改、保持冻结**,只是换了"坐标供给方"。
- 风险隔离:配准出 bug = 坐标偏,不会污染检测器内部。
- 本次漂移本身=识别层一次静默级联失败 → 按冻结纲领保险条款(归因识别层失败=自动解冻 case)有资格触发再评估。`([[pillar-confidence-doctrine]])`

## §3.5 ruler 锚已选定并验证(2026-06-22)`(实测)`

**锚 = ante 下注时的筹码图标**(每手开局全座同时下 ante → 8 座图标同帧出现;固定位短暂停留 ~0.4s 后飞向底池,只取固定位那一刻)。

**为什么是它**(对照 §3 五标准):① 每手都在 ✓(ante 必发)② 锐利 ✓ ③ 内容不变 ✓(同额 ante 同图标)④ 局部唯一 ✓(见下 NCC)⑤ 左右对称——否,但 per-seat 模板不需要(见下)。

**验证(`tools/field_hash.py --field anchor --ncc`,对 ante 帧 `--from-image`)**:
- **① 可定位性(关键)**:8 座自匹配 `2nd/peak = 0.14–0.18` → **每座搜索窗里峰尖锐唯一,可精准定位**。这是配准成败的属性,全过。
- **② 跨座一致性**:混合(s1≈s3、s5≈s7 达 0.99;其余 0.4–0.8)→ **不全一致,但不影响**:配准是"每座拿自己模板匹自己",**用 per-seat 模板,不用通用模板**。
- **③ 相对几何**:锚嵌入 roi_derive 镜像模型——左列{1,2,3}=`id+(105,59)`、右列{5,6,7}=`id+(-3,59)`(完美镜像:`122-20-105=-3`);s0/s4 中柱特例。即锚刚性绑座位面板,测它的漂移=该座漂移。

**⚠️ 陷阱**:`field_hash --live` 抓随机帧几乎逮不到 ante 那 0.4s → 会哈希背景出假结果(本会话踩过:s1/s2 假离群)。**验锚必须 `--from-image` 对真 ante 帧**。avg-hash 对小图标太粗(全 4–12 分不清),**用 `--ncc`**(NCC 模板匹配=配准同款度量)。

**字段落地(2026-06-22 rename)**:复用退役的 `timer` 槽 → 全栈 rename `timer→anchor`(`capture/roi.py` 字段+序列化+解析、`rois/party_poker_8.json` 8座 key、`roi_config` element/提示/画框、`roi_derive` 派生清单、`field_hash` 示例)。timer 决策倒计时职责 2026-06-15 已退役,槽腾出。**仅改 ROI schema/死字段,不碰冻结检测器(R-5 安全)**。

**配准实现(待基线后,本主题正文)**:事件驱动——hand-start ante 帧,每座取 `anchor` 模板在 `box±margin` NCC 匹配 → 峰位 = 实际位 → 减期望位 = 该座漂移 → 平移该座全 ROI。**搜索窗别太大**(够覆盖漂移即可,否则逮到飞行中的筹码)。**依赖 ante**:无 ante 桌需 fallback 锚。

## §3.6 锚-相对映射表已建(2026-06-22)`(实测)`

产出 **`rois/anchor_rel_party_poker_8.json`** = 配准的数据结构(各 ROI 相对 anchor 的 `[dx,dy,w,h]` 偏移)。结构:`left_template`(座{1,2,3}去噪中位)+ `right_template`(座{5,6,7})+ `centers.4`(s4 单列)+ `centers.0=null`(**待 s0 修复后补**)。死框 fold_text/hand_type 不收。

**左列模板(相对 anchor)**:`id[-105,-59,122,27]` `action[-65,-54,20,20]` `amount[23,-3,77,25]` `stack[-93,54,93,26]` `cards[-97,-29,105,77]` `fold_area[-83,-28,76,77]` `win_amount[-101,-84,113,28]` `button_indicator[8,60,12,14]` `card_marker[-88,38,8,8]` `showdown_corner[-97,37,10,11]`。右列见 JSON(独立存)。

**镜像自洽校验(关键发现)**:大图形框(id/amount/stack/cards/fold_area/win_amount/button_indicator)左↔右**完美镜像** ✓(`dx_右 = anchor_w − w − dx_左`)。但 **action / showdown_corner【不遵循镜像】**——它们是**文字/内容锚**元素(action=首字框、showdown_corner=摊牌白角),**镜像整改 a92ee01 之后才逐座手框**(action 06-12、showdown_corner 06-10),文字不镜像(左右座都从左读)→ 它们相对 **id 左缘**一致(action 两列≈id左+40~43、showdown_corner≈id左+8~12),而非图形镜像。card_marker ✗ = ±1px 小框噪声。

→ **设计铁律:左/右模板必须各列独立存储,严禁"左镜像推右"**(文字锚元素会推错;`roi_derive` 的纯镜像派生对这几个元素不适用,故它们当年是手框)。JSON 已分开存,note 里也标了。

**8 座全部入表**(2026-06-23):s1-s7 + s4 + **s0 已补**(`centers.0`)。s0 经几何套-3 + 重采 action 锚修复闭环(§3.7),其中柱偏移已算入。`pending` 清空。

## §3.7 s0 漂移 firefight 闭环(2026-06-23)`(实测)`

立题起因(§1)的 s0 整场动作全丢,本轮彻底修复并 live 验收关闭。

**根因(两层叠加)**:① UI 微调致 s0 整座 ROI **竖向漂 -3px**(横向 0,用户主张"复用 action 量得偏移套全框"= 对);② s0=hero,动作字号比对手座大(**hero-scale**)→ 即便框对正,call/bet/raise 首字 phash 仍对不上对手座采的全局锚(唯"过牌"碰巧匹配,故修前只 check 漏全部主动动作)。

**修复**:① 全 s0 框套 -3(id/dealer/+xx/stack/fold_area/cards/showdown_corner;action/amount 此前已重);② `build_action_refs --append` 用 **s0 自己的帧**补 跟/下/加 锚(每词 8→9)。**仅改 ROI 数据 + 参考,不碰冻结检测器。**

**验收三段**:离线 `probe_action_phash --ncc`(s0 跟16/下7/加19 命中)→ live 渐进(call→raise→bet 依次冒出)→ **live 74 手五动作全齐**(s0 check26/call19/bet3/raise8/all_in3,与对手座同量级)+ 单手深挖(s0 赢家手动作线完整,对照起点"赢家零动作"铁证反转)。

**教训固化**:① UI 漂移=**固定平移**,量一个框的偏移可套全座同型框(省重框);② hero 座因字号差,**per-seat 锚不可省**(对手座全局锚救不了 hero);③ 验识别必走 **离线NCC + live DB + 单手深挖** 三段,别只看计数。详见记忆 [[roi-drift-auto-registration]]。

## §4 风险(不藏)
- **锚可见性**:牌背角只在该座有牌时在 → 空座/弃牌后无锚。但**要精度的就是在打的活跃座**(尤其 hero),它们有牌时配准即可;空座不影响。**hero 须避开发牌窗/摊牌瞬间**(牌背变/消失)那几帧。
- **card_marker 更承重**:从"活跃集信号"升级成"全座配准基准" = 单点更关键。缓解:配准用独立锐角模板、card_marker 只做 canary,别全压一点。
- **搜索窗 vs 漂移幅度**:邻域搜索有上限,超窗即失败;"幅度不可控"需足够大窗或粗到细。

## §5 验收标准(先定死,否则做完不知道算不算成)
- **回放复现**:拿本次"旧漂帧 + 新帧",配准能**自动把 ROI 拉回正确位**,s0 动作恢复。`(待验)`
- **durability**:对人为/实测漂移多场景验证再算桩([[pillar-confidence-doctrine]]:验耐久才算桩)。
- **零回归**:配准上线后,未漂场景各座捕获率不退步。
- **canary 联动**:检出漂移→自动重配准(非静默级联),且有诊断事件可观测。
