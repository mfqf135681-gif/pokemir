## §0 定位:画像层第二通道,不是主线卡点

座位主键落地后(2026-06-13,解冻 case #2),**对账层已纯座位、不碰头像**;跨座识别只服务
**跨手画像聚合**(同一物理人坐过的不同座位归一起),而这件事**主要靠 OCR 名字**(文字不镜像、
跨座能读)。所以跨座 avatar phash 是"名字之外的第二通道"= 冗余增强。
→ **投入前先量化 OCR 名字通道的缺口(§1);缺口小则本主题可判"暂缓"。**

## §1 BASELINE 量化(2026-06-14,今天 14:29 场 123 手 / 1723 真动作)

**目的**:OCR 名字作跨座/跨手 key 有多脏?脏才值得 avatar 第二通道补。

| 指标 | 数值 | 解读 |
|---|---|---|
| 真动作数 / unique 名字 | 1723 / 42 | — |
| **脏名占比** | 纯数字 143(8.3%)+ Player_ 11(0.6%)+ TempUser 2(0.1%)≈ **9%** | OCR 完全没读出真名(读爆成数字/占位)= 硬洞 |
| **真名漂移伪重复** | 38 真名,difflib≥0.5 **仅 1 对**(`5UZ`/`SUZ`,S↔5 误读) | **OCR 真名通道比预期干净**——canonicalize+多帧众数已治掉大部分漂移 |
| **跨座聚合失败率** | ⏳ 待补 | 需 `seat_index`(座位主键 2026-06-13 刚落库,历史数据无)→ 收口测试新局后量化 |

### 🔴 反转性结论(数据驱动,可能降级本主题)
1. **OCR 真名通道已较干净**(38 真名仅 1 对漂移)→ avatar 第二通道补"真名漂移"的边际价值**低**;
2. **真正的洞是那 9% 纯数字/占位**(OCR 读爆)——但 **avatar 跨座本身崩(镜像),救不了这 9%**;
   且这 9% 属 OCR 读爆,归 #239 垃圾名护栏 + 数字识别,**不是跨座 phash 的菜**;
3. 故 avatar 跨座识别的**唯一**真价值 = "同人换座、OCR 名字也对、但要把不同座位归一物理人做
   跨手画像"——而这恰恰需 `seat_index` 才能量化失败率,**现在数据答不了**。
→ **暂不投入造识别器**;先做 §2(便宜)+ 等收口新局的 seat_index 跨座聚合失败率,缺口不大就封存本主题。

## §2 决定性实验:flip(下一步,最便宜)

记忆 [[player-id-recognition-approach]]:phash 同座稳(0-2)、跨侧崩(同人 41-50 ≈ 不同人 50-62),
框已验对称、崩在 hash 内容。**一个实验劈树**:同一玩家左侧 vs 右侧座位头像 crop,**一侧水平翻转**
再比 phash hamming —
- 掉到 0-8 → **纯镜像**,flip 归一化几行解决(整问题塌缩成小修);
- 仍 40+ → 头像内容真不同,phash 难走,换特征(§3)。
**前置**:用换座录制取同人不同座干净帧(§4)。

## §3 候选特征谱(若 §2 非纯镜像,按成本排)
- **颜色直方图**:天然对水平镜像不变(翻转不改颜色分布);区分度低,做粗筛/配 phash;
- **flip-phash 组合**:min(hash, flip后hash) 的 hamming;
- **行为指纹(非视觉)**:换座时栈带走 → 上手末栈 ≈ 下手初栈 + 同时消失/出现(弱,独立通道);
- **CNN embedding**:重,YAGNI,前面都不行再上。

## §4 验证基建(已有)
自定义房可控换座录制 + `--frames` 直接比同人不同座的干净帧([[player-id-recognition-approach]] 记此法)。
live 无法控制谁换座 → 这是跨座识别唯一能干净验证的方法,任何方案前置。

## §5 红线
- **R-1 image-only**:头像 crop = 截图,合规;
- **反 dim-creep**(圈梁纪律):先证 1 维 ROI 再扩,别一口气上 CNN;
- **R-5 冻结**:接入 live 识别 = 解冻 case,走流程(归因→登记→修→回归→回冻);只补 alias、不当独立 key。
