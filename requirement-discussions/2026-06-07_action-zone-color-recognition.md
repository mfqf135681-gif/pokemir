## 0. 一句话
动作区**不该用 OCR**。WePoker 出动作时整区被**纯色填充**(跟注/下注=蓝、加注=橙、让牌=绿)→ **取平均色判别**;蓝组(跟注/下注)**用游戏状态分**(本街有没有注),不读字。**零 hash、零 OCR。**

## 1. 背景:动作 OCR 是伪命题
- 动作区(`action_area`,~42×21)出动作时显**纯 2 字动作词 + 纯色背景**;idle 时显玩家 ID。
- 此前 action 读走 EasyOCR(allowlist `跟注让牌加下`)→ idle 帧被 allowlist 逼出垃圾([[ocr-allowlist-double-edge]]),靠 parser 丢弃;真动作帧才有效。
- recognize-only(#237)只是把这条 OCR 加速 ×3——但**纯色背景下,根本不用读字**。

## 2. 设计:动作区色彩判别
**用户实战桌观察(信息对齐):动作区仅 4 个动作,各带纯色背景:**
| 平均色 | 动作 | 单凭色可定? |
|---|---|---|
| 🟠 橙 | 加注 raise | ✅ 唯一 |
| 🟢 绿 | 让牌 check | ✅ 唯一 |
| 🔵 蓝 | 跟注 call / 下注 bet | ❌ 共蓝,需再分 |
| (无填充/ID) | idle 无动作 | 不匹配=无动作 |

### 蓝组:用游戏状态分,不读字(§15 解不读)
- **下注(bet)只在"本街尚无注"时发生(开池第一枪);跟注(call)只在"已有注要跟"时发生。**
- → **蓝 ∧ 本街已有注 = 跟注;蓝 ∧ 本街无注 = 下注。** 重建逻辑本就追踪"本街有无注",信息免费。
- **翻前特例自洽(用户验证)**:翻前 BB 是站着的注 → 翻前蓝色永远=跟注(翻前第一个行动者跟大盲显"跟注"非"下注")。规则天然吃下,无需特判。

### fold / all-in:不在动作区
- **弃牌**:头像区(#235 活跃集 phash)。
- **all-in**:头像区显 "allin" 两字母(用户对齐)。→ 归 #235 头像区体系,动作区不管。

## 3. 为什么对:持久态 + 顺手解了频率瓶颈
### 3a. 动作色是【持久态】(正中 ring-beam 哲学)
动作色**稳定显示到本街结束** → **1Hz 随便抓得到**(一动作横跨多 tick),非 +xx 那种 1-2s 瞬态。
**唯一瞬态 = 每街最后一个行动者**(他一动街就翻,窗口极短)→ 从游戏状态反推(街翻+底池涨+轮到谁 → 他做了啥),交求解器兜。

### 3b. 顺手把"频率瓶颈"从根上解了
tick 750ms 里 **action OCR 242ms(27%)+ fold OCR 417ms(46.6%)= 73%**。本设计把这两大头换成近免费:
- action 242ms → **平均色(微秒级)**;
- fold/all-in 417ms → **头像区 phash(#235,已验)**。
→ **tick 投影 ~140ms ≈ ~7Hz(标:投影,待实测)。全程同步,recognize-only 不用、解耦硬仗也不用打。**
**真正的解不是"加速 OCR",是"动作区压根不该 OCR"——颜色 + 游戏状态。**

## 4. 🔴 待验闸(先测后建)
1. **色簇分离**(唯一硬闸):各动作 `action_area` 平均 HSV 是否成 4 个不重叠簇(蓝/橙/绿/idle)。用户称"肉眼可分"→ 基本稳赢,**仍出探针量化**(廉价、一锤定)。
2. **蓝组游戏状态可靠性**:call/bet 劈对依赖"本街有无注"追踪准——继承重建状态可靠性(本就是求解器要做的;混了影响也小)。
3. **最后行动者瞬态**:每街末位窗口短,1Hz 可能漏 → 求解器反推兜(已知缺口,非阻塞)。
4. **渐入动画中间色**:1Hz 若抓到填充渐变帧,平均色发飘 → 看纯色稳定期多长 / 取区域众数色而非均值抗飘。

## 5. 决定 / 路线
- **#237(recognize-only)对动作区 park**:动作不 OCR 了,它失去用武之地;**代码留着 flag-off**(无浪费;将来若有别的纯文本读如玩家名再说)。
- **#235 扩展**:头像区 phash 统管 **fold + all-in**。
- **新增任务**:动作区色彩判别(平均色 → 橙/绿/蓝;蓝组游戏状态分 call/bet)。
- **路线**:① 色簇分离探针(DEV)→ ② 过则实装动作色判别 + #235 扩 all-in → ③ 重测 tick Hz(验 ~7Hz 投影)。

## 6. 待开发功能(backlog,用户明示记录)
- **空桌/全桌状态重采工具**:桌皮由用户可控;换皮后色值 profile 会变 → 预留工具一键重采全桌空桌基线(色簇参考 + 各 ROI 空基线)。优先级:换皮时触发,非主线。

## 7. 严限 / 未决
- 色值 profile 绑定桌皮(见 §6 工具);
- 蓝组依赖街级"有无注"状态,该状态本身的可靠性是上游问题(求解器范畴);
- 投影 ~7Hz 待实装后实测,勿当既成。
