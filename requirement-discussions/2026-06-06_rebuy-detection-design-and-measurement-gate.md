## 1. 要解决的问题

#226 筹码级重建用 per-hand stack 端点(`player_stacks_initial`/`final`)算每手 per-seat 净额/赢家。
**痛点:`final > initial`(stack 涨)有两个原因 —— ① 赢底池 ② rebuy 重新买入 —— 端点本身分不开(简并)。**
实测:rebuy 手被正确标 `conservation_ok=false`(Σnet 大正)+ `multi_winner`,但**净额无法重建**。
rebuy 污染**局部化**于发生那一手(前后手干净,实测 s1 全轨迹证)。

## 2. 当前最佳设计(逐步收敛出来的)

**核心:用一个独立"是否赢"信号破简并。最终落在 +xx(派彩浮层)的 phash 门控。**

### +xx 三料桩(关键升维:读"在不在"易,读"是多少"难)
| 角色 | 机制 | 置信(设计预期)|
|---|---|---|
| (a) 二元"赢没赢" | +xx 区 phash vs **空桌基线** 有无变化 | 高 |
| (b) 读赢额的闸 | phash 突变=浮层最新鲜 → 此刻 OCR 赢额(避横幅/消失污染)| 中高 |
| (c) 守恒第4锚 | 赢额 ≈ pot−rake ≈ 赢家stack涨+投入 | 交叉验证;**可顶替会超读的 pot**(治5e60)|

### 严时间闸 = 巧合(防污染)
横幅公告/用户发言气泡会让 +xx 区 phash 乱变 → **单看"+xx变了"不够**。
**判赢 = "+xx 变 ∧ 同刻该座 stack 突涨" 巧合**(污染不会同时让 stack 跳)+ 仅手末派彩窗口
(rebuy 涨在手间、win 涨在手末,时点天然分离)。三路互验(stack涨/赢额/pot−rake 一致)兜底。

### rebuy 判定式(全高置信,零裸OCR金额依赖)
`rebuy = stack突涨 ∧ +xx无 ∧ (落圆整买入档 ∨ 发生在手间)`
命中 → 该玩家本手净额标"reload污染、不可用",**但 final 续到下手 initial**(轨迹不断);
其余玩家 + 真赢家照常守恒重建。圆整买入档 per-table 学习(像 D25 rake 学习)。

## 3. 🔴 批评:整套压在未验假设上(明天必先测)

**致命级:**
1. **+xx live 行为零数据**:① 是否**每种赢都显**(尤其翻前无对抗赢)?不显 → "无+xx=rebuy" 对所有无对抗赢误判。② presence phash live 稳不稳?③ **捕获率**(说了几轮"命门未验",至今没量成,query 超时)。**整个破简并逻辑从根上依赖它,却一个数据没有。**
2. **1Hz 撞 +xx 瞬态**:+xx 闪 1-2s,1Hz 可能整帧没采到 → "无+xx" 歧义(没赢 vs 没采到)。"巧合闸"在粗采样下两信号差一 tick 就对不上 → 真赢误判 rebuy。**瞬态根 = tick 率,没动。**

**结构级:**
3. **stack 端点可能恰在 all-in/rebuy 手崩**:rebuy 前必 all-in 输光,而 all-in 时 stack 区显胜率%不显筹码(R15)→ 破产者 final 可能读成%/失败,非干净 0。**端点桩在"rebuy 那类手"里最不可信**;"24/25守恒"多是小手(强制注占大头),大 all-in 手未单独验。
4. **圆整买入档 = n=1**(就 800):top-up 可能任意额、买入可能多档、筹码单位下是否圆整未知。脆。
5. **rebuy 频率未知且剧烈波动**(一段4% 一段57%)→ 可能过度工程。
6. **"rake 恒 ~12" 疑系统性偏移非真rake**(不同底池都≈−12,不像%抽水)→ "守恒闭合到rake级"可能是"闭合到固定误差级"。

**元批评**:连续几轮在无 live 数据下精修设计 → 越设计越顺=因为还没碰现实。违 data-driven 铁律。
